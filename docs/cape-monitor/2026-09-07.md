## Changes Detected — Code Updated

### 1. CAPE Phase 2 Live (June 29, 2026) — `src/lib/tariff-calculator.ts` updated

**What changed:**  
CBP deployed Phase 2 of CAPE on June 29, 2026. Phase 2 expands eligibility to cover entries **flagged for reconciliation** (types 01, 02, 06) where a corresponding reconciliation entry (Type 09) has **not yet been filed**.

**Scope:** Unliquidated entries and entries within 80 days of liquidation (same as Phase 1).

**Critical filing sequence (Phase 2):**  
The CAPE declaration MUST be submitted BEFORE the Type 09 reconciliation entry. If the Type 09 is filed first, the underlying entries are **permanently** locked out of the Phase 2 refund path. This was confirmed as the leading cause of Phase 2 rejections.

**Scale:** ~$28.7 billion in additional refunds across ~2.8 million entries (per CBP executive assistant commissioner testimony at June 9, 2026 CIT hearing).

**What still remains excluded from all CAPE phases:**
- Type 47 (drawback)
- Type 08 (duty deferral)
- Type 23 (TIB)
- Type 09 itself (the reconciliation summary entry — CAPE does not accept Type 09 directly)

**Code changes made (`src/lib/tariff-calculator.ts`):**
- Added `cape_phase2` and `cape_phase3` to the `FilingMethod` union type
- Added `isReconFlagged?: boolean` and `hasReconFiled?: boolean` to `EntryForEligibility` interface
- Added `"excluded_recon_filed"` to the `EligibilityResult` status values
- `checkEligibility()`:
  - New check: if `isReconFlagged && hasReconFiled` → `excluded_recon_filed` (locked out of Phase 2)
  - Within 80-day window + `isReconFlagged` → `filingMethod: "cape_phase2"` + critical ordering review note
  - Unliquidated + `isReconFlagged` → `filingMethod: "cape_phase2"` + critical ordering review note
- Updated `EXCLUDED_ENTRY_TYPES` comment to distinguish Phase 1/2 exclusions
- Updated entry type exclusion error message to say "all CAPE phases" instead of "Phase 1"
- Updated `getRoutingBucket` comment to mention `excluded_recon_filed`

### 2. CAPE Phase 3 Planned but DELAYED (as of August 25, 2026)

**What happened:**  
CBP confirmed that Phase 3 — which would cover "finally liquidated" entries (>80 days since liquidation) — is **temporarily delayed** to build new validations. No new launch date announced.

**Legal background:**  
On July 17, 2026, U.S. CIT Senior Judge Richard Eaton ordered CBP to reliquidate entries liquidated more than 80 days ago on which IEEPA deposits were made. The U.S. government is contesting this at the Federal Circuit. 3,700+ cases are before the CIT seeking refunds of amounts deposited as IEEPA duties ruled unconstitutional by the U.S. Supreme Court earlier in 2026.

**Current path for 80–180 day entries:** Formal protest under 19 U.S.C. §1514 — the code now advises filing a protective protest while Phase 3 is delayed, with a review note that Phase 3 will offer an additional path once live.

**Current path for >180 day entries:** CIT litigation only (unchanged); Phase 3 is anticipated but not live.

**Code changes made (`src/lib/tariff-calculator.ts`):**
- 80–180 day entries now carry a `needsReview: true` flag + explicit `reviewNote` about Phase 3 delay and the importance of filing a protective protest.
- The `protest` `filingMethod` is preserved for this window (Phase 3 not added until it goes live).

## No-Code Findings (Documentation / Alert Items)

### 3. Rejection Rate Updated: ~19% (was ~15%)

The overall CAPE rejection rate has risen from the previously known ~15% (CBS News) to approximately **19%** as of recent reporting. Of 11,222,927 entries that passed file validation, 2,124,394 were rejected.

**Most common rejection reasons (unchanged):**
- `ENTRY ON DRAWBACK`
- `PROTEST ON ENTRY`
- `ENTRY SUMMARY UNDER REVIEW`
- `NO IEEPA HTS ON ENTRY`
- `STATEMENT PROCESSING NOT COMPLETE`
- (New, Phase 2) Type 09 filed before CAPE declaration

### 4. ACH Enrollment Alert — $1.7 Billion Held

As of August 21, 2026, **22,170 refunds totaling approximately $1.7 billion** have not been transmitted to Treasury because ACH bank account information is missing or incomplete in ACE.

**Implication for broker clients:** Any importer that has not enrolled their bank account in ACE under the *ACH Refund Authorization* tab will have their refund held indefinitely. This is a high-impact action item to surface to clients.

### 5. CAPE Scale as of August 21, 2026

- $132.5 billion in IEEPA refunds accepted for CAPE processing
- $106.6 billion completed and sent to Treasury

### 6. New ACE Reports Available

CBP released new and enhanced ACE reports to monitor CAPE declarations and refund statuses:
- **REV-615 (Trade CAPE Detail Refund Report):** New — tracks refund progress including secondary statuses: Sent to Treasury, Treasury Issued, Funds Diverted, Check/ACH Returned
- **REV-603 (Entry Summary Report / Trade Refund Report):** Tracks both status and total refund amount per importer
- **REV-613 (ACH Rejected Refunds Report):** Lists rejected declarations due to "incomplete ACH Refund enrollment"

No changes to CSV format (still single-column `Entry Number`), batch limit (9,999 entries), or filer eligibility (IOR or original licensed broker only; attorneys still cannot file). ABI still not supported; web portal only.
